## 0. 评审速览

### 0.1 一句话结论

工程已从「页面脚本驱动 + 多套隐式通道」重构为**四层正交架构**：数据（L0/L1/L2）→ 算法（18 单元）→ 空间（Layout/Region/Module）→ 容器（两个 Container / 一个公开根组件），并以 `data` / `config` 两个结构化属性 + CustomEvent 作为唯一对外契约，通过框架无关内核适配 React / Vue / Svelte / Angular / Solid·Preact / 原生六类调用方。

### 0.2 变更全景

| # | 设计决策 | 原状态 | 当前状态 | 落地 | 主要验证 |
|---|---|---|---|---|---|
| A | 数据分层与算法单元化 | 10 个 JSON 输入、`any` 205 处、算法按文件散落 | 5 个 L0 落盘输入 + 5 个运行时派生（含逐笔 `trades`）；18 个算法单元；0 显式 `any` | ✅ | 8 条跨图关联闭合、产物 hash 一致 |
| B | 容器 / 布局 / 模块架构 | `ChartContext` 一肩挑状态/布局/渲染，`pane` 六义 | 四层正交、两个 Container、`MODULE_REGISTRY` 11 项 | ✅ | 布局 18 场景 294 项一致、装饰 2736 float 一致 |
| C | 组件封装与标准化数据契约 | `index.html` 2028 行、组件组件 DOM/CSS/逻辑散在页面、`dataset="./src/data"` | `<stock-workspace>` 单根组件、页面当时 255 行 / 当前 156 行、`data`/`config` 注入 | ✅ | 8 场景 0 JS 错误、页面零残留 |
| D | 跨框架适配层 | `./react`/`./vue` 绑定旧 setter，对新组件静默失效 | 内核 + 六类框架桥 + 注入式组件工厂 | ✅ | 当时 80/80、当前 97/97 测试、第三方三种 TS 配置 0 错误 |

### 0.3 建议评审人重点回答的 5 个问题

1. **`data`/`config` 是否应成为长期稳定契约**？对象属性而非 HTML attribute，意味着所有框架都必须通过 ref/指令赋值——是否接受这一约束？
2. **light DOM 是否足够**？当前无样式隔离、不可多实例（全局 CSS + id 冲突）。是否需要立项 Shadow DOM？
3. **注入式组件工厂** `createReactWorkspace(React)` 由使用方传框架实例，零依赖但需多写一行胶水代码——是否可接受，还是应改为 `peerDependencies` 提供原生组件？
4. **旧 API 废弃节奏**：`bindStockChart` / `vStockChart` / `getContext()` / `dataset` 属性均已标 deprecated 但保留，何时移除？
5. **L2 示意数据边界**：仅 `depth` / `orders` **2 个**数据集需交易所授权（`level2-licensed`），`auction` 为 `l1-intraday-only` 示意、`trades` 已改为运行时派生不落盘；真实逐笔委托/完整委托簿无法由公开数据反推，工程以确定性 mock 呈现——产品化时的数据接入方案是否明确？

## 1. 背景与目标

### 1.1 原始问题

> 以下为四轮重构前（当时状态）的问题盘点，数字与结论均为当时值，不代表当前代码。

- **类型**：工程 `strict: true` 却有 205 处显式 `any`，与 strict 初衷相悖；手写 `.d.ts` 与源码两套声明漂移。
- **数据**：10 个业务 JSON 中仅 2 个是真实公开行情输入，其余 8 个是构建期派生却被当成独立输入；各图数值互不闭合（分时累计额与日 K 差 22804.62 元、逐笔 242/242 分钟 amount 不等、委托流两套状态机、多日量额差 3~4 倍）。
- **算法**：按「图表/文件职责」而非「算法概念」分割，同一概念 2~7 份实现；构建期与运行时靠 JSON 与编译产物间接耦合。
- **架构**：`ChartContext` 同时承担状态真源、布局计算、渲染编排；`pane` 一词六义；「三列两行」实为 canvas 像素分区却常被当成 DOM 结构。
- **组件边界**：`index.html` 2028 行，其中 122 条 CSS（88%）与约 830 行脚本在做组件状态镜像；页面通过 13 种通道越过组件边界（`chart.setXxx()`、`attachCover()`、`querySelector('.cover-*')`、`getState()` 等）；`dataset="./src/data"` 让组件自己 fetch 路径。
- **框架适配**：`./react`/`./vue` 绑定旧组件 13 个 setter，对新根组件静默失效；JSX 声明与事件映射未覆盖新契约。

### 1.2 设计目标

| 目标 | 可度量的验收口径 |
|---|---|
| **以市面可得数据为基准** | 外部输入收敛到公开日 K + 当日分时 + 静态股本；需授权数据显式标注、本地 mock |
| **尽量少依赖外部数据** | 可计算的数据一律运行时派生，不落盘 |
| **概念统一、算法为分割单元** | 同一概念单一实现；算法以概念分模块并登记元数据 |
| **概念层次清晰** | 四层正交、单向依赖、术语消解表 |
| **常规组件范式** | 一个自定义标签 + 属性/方法输入 + 事件输出；页面不探入组件内部 |
| **跨框架可用** | 六类框架桥共享同一内核，包零框架运行时依赖 |

### 1.3 非目标（明确不做）

- 不实现 Rust/WASM 多线程计算内核（`docs/03` 为规划，当前 `JsComputeEngine`）。
- 不提供实时行情端点、不做投资决策功能。
- 不引入 `peerDependencies`、不锁定 React/Vue 版本。
- 不把 L2 示意数据替换成真实授权数据源（产品化议题）。
- 本轮不实施 Shadow DOM 与多实例隔离（见 9.2）。

## 2. 总体架构

```text
Workspace  页面工作台：加载数据 / 解析 URL / 订阅事件，不做空间计算
   │
   ├── Container  main-canvas（<stock-chart>，WebGL）
   │              detail-canvas（<detail-canvas>，DOM 覆盖层）
   │                 └── Layout  纯数据 Region 树
   │                        └── Region  rect / target / visible / z / constraint
   │                               └── Module  由 Registry 安排到槽位
   ├── Data       L0 外部输入 → deriveDataset() → L1 运行时派生；L2 授权示意输入
   ├── Algorithms 18 个纯 TS 单元 + ALGORITHMS 注册表（构建期 / 运行时共用）
   └── Frameworks controller 内核 → React / Vue / Svelte / Angular / Solid·Preact / 原生
```

**四条原则**

1. **职责正交**：状态（Context）/ 空间（Layout）/ 介质（Container）/ 内容（Module）互不兼任。
2. **单向依赖**：`Module → Region → Layout → Container → Workspace`；反向只允许事件。
3. **单一真源**：常量、算法、口径、布局、数据契约各一处权威定义。
4. **结构化输入输出**：组件只接受对象（`data`/`config`），只输出 CustomEvent；不读路径、不读 URL、不读全局状态。

> 概念精确定义、术语消解表与依赖索引以 `docs/00` 为准；本文件只描述**设计决策与权衡**。

## 3. 设计决策 A：数据分层与算法单元化

### 3.1 问题

> 以下为该轮改造前（当时状态）的盘点，数字均为当时值。

10 个业务 JSON 中只有 `bars_1d.json`（935 根公开日 K）与 `intraday_20261113.json`（267 点公开分时）是真实外部行情；其余 8 个均由构建期固定种子生成却被当成输入。跨图数值断裂：分时 15:00 累计额 ≠ 日 K `amount`（+22804.62 元）、逐笔 amount 242/242 分钟与分时不等、委托流 261 条悬空挂单且两套状态机、多日前 4 日量额约为日 K 的 3~4 倍。

### 3.2 决策

| 层 | 内容 | 落盘 |
|---|---|---|
| **L0 外部输入** | `bars` / `intraday`（公开行情）+ `manifest.json` + `raw/instrument.json` | 是 |
| **L2 示意/授权输入** | `depth` / `orders`（**2 个** `level2-licensed`，需授权、无法由分钟数据反推）+ `auction`（`l1-intraday-only` 示意） | 是 |
| **L1 运行时派生** | `chips` / `intradayMulti` / `depthFull` / `depthScenarios` / `trades`（495 条，`buildTradeSeries(intraday)`）、分钟 K、全部副图指标、盘口金额、逐笔方向 | **否** |

> **本轮输入层精简**：`manifest.files` / `provenance` 收敛为 **5 键**，`trades_20261113.json` 已删除、`trades` 不再落盘；落盘字段精简为 `intraday` 5 / `auction` 7 / `depth` 顶层 3 + 每档 2 / `orders` 7 / `bars` 13，累计量额、均价、`orderCount`、`limitState`、`tag`、`trend` 等由 `deriveDataset()` 在运行时补齐，**对外 `ChartDataset` 语义不变**。

`src/core/derive-dataset.ts` 为数据分层枢纽：L0 → L1 生成 + 跨图闭合修正（累计量额重算锚定日 K、逐笔按分钟锚定分时、委托守恒、多日量额锚定 bars、远档挂单补全）。`src/algorithms/` 18 个纯 TS 模块按概念分割，`ALGORITHMS` 登记 `{ id, concept, inputs, outputs, sharedBy, pure }`；`scripts/` 三个工具改为薄 re-export，构建期与运行时共用同一实现。

### 3.3 收益与权衡

- **收益**：`manifest.files/provenance` 收敛为 **5 键**（当时历经 10 键 → 6 键），累计删除 5 个 JSON（4 个中间数据集 + `trades_20261113.json`）；8 条跨图关联实测差 0；205 处显式 `any` → 0；声明由 tsc 自动生成。
- **权衡**：派生计算前移到浏览器加载时（一次性成本，当前数据集 935 根日 K 下可忽略）；仅 `depth` / `orders` 2 份 Level-2 示意数据仍需落盘（真实逐笔委托/完整委托簿信息在分钟聚合中已不可逆地丢失），逐笔明细 `trades` 不再落盘、由 `buildTradeSeries(intraday)` 运行时生成 495 条。
- **已修口径**：撮合候选价补申报价间 0.01 步长中间价；`r2` 统一 half-up；换手率统一 `%`；`trim` 统一 0 位小数；涨跌幅按各交易日昨收。
- **输入层与市面口径对齐**：落盘 `volume` 为**股**（东财原生「手」× `LOT_SIZE=100` 转股），`auction.matchedQty` / `unmatchedQty` 为**手**，`depth.bids/asks[].volume` 为**股**（市面十档常显示「手」，差 100 倍）；`turnoverRate` / `pctChg` / `amplitude` 为 **% 数值**（0.33 = 0.33%）、`change` 为元、日线 `timestamp` 取交易日 00:00 UTC 毫秒；所有手股换算统一用 `LOT_SIZE`。`manifest` 新增逐数据集 `units` 5 组、`demoPatterns` 4 项，删除 11 个零消费者字段（`market/timezone/currency/interval/source/afterHours/l2/floatSharesSource/palette/upColor/downColor`）；四态演示形态改由 `demoPatterns` 记录、`deriveDataset()` 内存叠加 `limitState`，落盘 `bars` 保持东财原生、不再注入改写 OHLC。

## 4. 设计决策 B：容器 / 布局 / 模块

### 4.1 问题

`ChartContext.applyLayout()` 一个方法混合读状态、读 DOM hints、算十余个矩形、回写 `pane.rect`、回调宿主、派事件、触发重绘八件事；布局计算散落三处（core 像素矩形 / `syncSideBars` CSS 变量 / 页面覆盖视图 Grid）；渲染层另有约 8 个「无主装饰批次」。

### 4.2 决策

- `src/architecture/` 定义 `Container` / `Layout` / `Region` / `Module` / `ModuleRegistry` 契约与 `TERMINOLOGY` 映射。
- `MainCanvasLayout.compute()` 为纯函数，产出 `LayoutSnapshot`（Region 树 + `paneRects` + metrics），**零副作用**；`ChartContext.applyLayout()` 退为适配层，负责应用结果与三个副作用。
- `CanvasDecorationModule` 收拢左坐标栏、时间轴带、分界线、竞价列灰底。
- `<detail-canvas>` 成为第二个正式 Container，接管覆盖视图骨架、`DetailCanvasLayout`、ResizeObserver 与销毁。
- 公开标签保持零破坏：7 个原有标签不变，新增 `detail-canvas` 为第 8 个。

### 4.3 收益与权衡

- **收益**：概念消解（`pane` 六义 → Module / Region.rect）；布局计算单点；装饰批次有归属。
- **验证**：`MainCanvasLayout` 与旧算法 **18 场景 / 294 项逐字段一致**；装饰批次 **6 场景 / 2736 个 float 逐位一致**（守住了 WebGL 全局坐标 + `gl.scissor` 契约）。
- **保留边界**：批次插入 `geometries` 的编排仍在 `renderFrame`（若上移到 Container 需另立渲染管线重构）；采用 light DOM，无样式隔离。

## 5. 设计决策 C：组件封装与标准化数据契约

### 5.1 问题

`index.html` 的 `<main>` 里 122 条组件级 CSS、约 150 行 DOM、约 830 行脚本都在做组件状态镜像；页面通过 13 种通道反向读写组件内部；`dataset="./src/data"` 让组件自己 fetch 路径，违背常规组件范式。

### 5.2 决策

**新增 `<stock-workspace>` 作为唯一公开根组件**（light DOM，视觉零变化），内部私有持有 `<stock-chart>`（绘图）、`<trade-tape>` / `<depth-book>` / `<detail-canvas>`，以及头部行情、工具栏、明细卡片、详情覆盖视图。`src/workspace/` 按职责拆 6 个模块：`types` / `template` / `head` / `controls` / `detail` / `url-config`。

| 方向 | 契约 | 页面职责 |
|---|---|---|
| 数据输入 | `workspace.data = ChartDataset`（结构化对象） | `loadDataset('./src/data')` 后赋值 |
| 配置输入 | `workspace.config = Partial<WorkspaceConfig>`（增量合并，25 字段） | `parseWorkspaceConfig(URLSearchParams)` 一次性赋值 |
| 状态输出 | `WORKSPACE_EVENTS` + 内部事件冒泡（CustomEvent） | 只订阅事件做诊断 |
| DOM 耦合 | `attachCover` / `attachDetailCard` / `coverRegion()` 收为组件内部 | 无 |

**兼容**：`dataset` 路径属性保留在 `observedAttributes`，仅发 `console.warn` 并标 `@deprecated`，不再加载数据。

### 5.3 收益与权衡

- **收益**：`index.html` 2028 行 → **255 行**；页面残留 `dataset="./src/data"`、`chart.setXxx()`、`attachCover`、`querySelector('.cover-*')`、`getState()` 均 0 处；组件不 fetch / 不读路径 / 不解析 URL / 不读全局状态。
- **权衡**：light DOM 下 CSS 仍是文档级选择器（由组件 `ensureStyles()` 注入），存在全局串扰与 id 冲突，暂不支持多实例。
- **已修回归**：`?tape-zoom=1` 需映射为 `tapePlacement:'detail'` 才打开覆盖视图；默认空 `movingAverages` 不得覆盖 `<ma-line>` 声明式子节点。

## 6. 设计决策 D：跨框架适配层（本次评审重点）

### 6.1 问题：旧适配层对新组件静默失效

审查确认 `src/frameworks/react.ts` / `vue.ts` 绑定的是旧 `<stock-chart>` 的 13 个 `setXxx` setter 与 `dataset` URL attribute：

- `options.data` 调 `el.setDataset?.()` —— `<stock-workspace>` 无此方法，赋值**静默丢弃**；
- `config` 未列入 `StockChartBinding`，被 `[key:string]: unknown` 吞掉，运行时无分支；
- `data` 用真值判断，无法传 `null` 清空；`setAttribute!` 在纯 `EventTarget` 测试宿主上会抛；
- `vStockChart.updated` 仅 `===` 引用比较后**全量解绑重绑 + 全量重放 13 个 setter**，与组件浅合并增量语义不对齐；
- `WORKSPACE_EVENTS` 未进事件映射，JSX 声明无 `data`/`config`，无 `onXxx` 类型。

### 6.2 架构：框架无关内核 + 各框架生命周期桥

```text
        createWorkspaceController(el, props)      ← 唯一实现，零框架依赖 / SSR 安全
         ├─ data   : 引用比较 → el.data（含 null 清空）
         ├─ config : diffConfig 逐 key → el.config = patch
         ├─ events : on 字典 ∪ onXxx 驼峰 → addEventListener（强类型 detail）
         ├─ update(next) : 只处理差异，不解绑重绑
         └─ destroy()    : 解绑全部
              │
   ┌──────────┼──────────┬──────────┬───────────┬──────────┐
 React       Vue       Svelte     Angular   Solid/Preact   原生
 ref binder  指令 +     action     WeakMap    信号绑定      mount
 + 注入式    composable  指令        props 分离
 组件工厂
```

**分层理由**：把「怎么写数据/配置、怎么订阅事件、怎么 diff 更新」收敛到一处，各框架只负责「何时拿到元素、何时更新、何时销毁」，避免六份实现各自漂移。

### 6.3 统一 Props 契约

| 字段 | 类型 | 语义 |
|---|---|---|
| `data` | `ChartDataset \| null` | 引用变化才赋值；`null` 可清空（区别于旧实现真值判断） |
| `config` | `Partial<WorkspaceConfig>` | 逐 key 浅 diff，只把变化字段作为 patch 传给组件 |
| `on` | `{ [eventName]: (ev: CustomEvent<T>) => void }` | 事件名字典，`detail` 强类型 |
| `onXxx` | 10 个具名驼峰属性 | 自动转 kebab-case 事件名；`onThemeChange` → `theme-change` |

`WorkspaceEventMap` 继承 `StockChartEventMap`（`Omit` 掉 `dataset-ready` 后覆盖），补入 `workspace-ready` / `workspace-config-change` / `workspace-status` 等 detail 类型。

> **设计取舍**：曾尝试用模板字面量索引签名 `[key: \`on${string}\`]` 给所有驼峰回调统一类型，但 `on` 属性名本身匹配该模式导致 TS2411 冲突。最终采用「10 个常用具名属性 + 其余走 `on` 字典」——类型更精确，且不牺牲任意事件的灵活性。

### 6.4 六类框架适配对照

| 框架 | 主要 API | 形态 | 是否需传入框架实例 |
|---|---|---|---|
| React | `createWorkspaceRef`（React 19 ref cleanup）、`bindWorkspace`、`createReactWorkspace(React)` | ref binder + 注入式组件工厂 | 仅组件工厂需要 |
| Vue | `vWorkspace`、`createVueWorkspace(vue)`、`useWorkspace` | 指令（`updated` 只增量 update）+ composable | 仅组件工厂需要 |
| Svelte | `workspaceAction` / `stockWorkspace` | `use:` action，返回 `{update, destroy}` | 否 |
| Angular | `createWorkspaceDirective()`、`createAngularWorkspace(ng)` | WeakMap 按元素隔离的纯指令对象 | 仅组件工厂需要 |
| Solid / Preact | `splitWorkspaceProps`、`createWorkspaceSignalBinding`、`createPreactWorkspace` | 信号绑定 + props 分离 | 仅工厂需要 |
| 原生 | `mount` / `mountWithData` | 显式可选 IO（组件默认仍不 fetch） | 否 |

**零框架运行时依赖**：所有工厂用本地 `ReactLike` / `VueLike` / `SvelteLike` / `AngularLike` / `SolidLike` interface 描述注入对象，包无 `dependencies` / `peerDependencies`，不锁版本；适配层不触碰 `document` / `window` / `customElements`，SSR 可安全 import。

### 6.5 兼容与废弃策略

| 旧 API | 处理 |
|---|---|
| `bindStockChart` / `vStockChart` / `StockChartBinding` | **函数体逐字未改**，仅加 `@deprecated` 指向新 API；原 Vue 指令与类型探针测试仍通过 |
| `dataset` 路径属性 | 保留 observedAttributes，仅 `console.warn` |
| `getContext()` | 只读门面 + `@deprecated`，下个主版本可能移除 |

### 6.6 评审证据：过程中修掉的两个真实缺陷

1. `camelToEventName('onThemeChange')` 原返回 `'-theme-change'`（前导连字符），**驼峰回调收不到任何事件** → 改为首字母单独小写再处理后续大写，得 `theme-change`；测试同步去掉兼容 strip。
2. `onXxx` 被 `[key:string]: unknown` 吞成隐式 `any`（第三方 TS 探针首次暴露）→ 改为具名属性给出精确 `CustomEvent` detail 类型。

这两项均由「独立第三方 TS 消费者探针」与行为测试发现，说明跨框架契约不能只靠实现自测。

## 9. 风险、权衡与未决项

| # | 项 | 影响 | 建议 |
|---|---|---|---|
| 9.1 | **light DOM 无样式隔离**（主题已收进组件，样式作用域仍待立项） | 全局 CSS 选择器 + id 冲突，暂不能同页多实例 | 若有多实例需求，立项 Shadow DOM；需重写 `--sw-*` 变量继承链、`slot="side"` 分配与跨 shadow 事件 |
| 9.2 | **组件内部仍保留 `ChartApi` 反向调用** | `stock-workspace` 内部把 config 映射到 `<stock-chart>` 的 setter，属组件内部实现而非对外通道 | 可接受；若 `<stock-chart>` 未来也改为纯属性输入，需同步改造 |
| 9.3 | **`WORKSPACE_EVENTS.STATUS` / `ERROR` 未主动派发** | 声明存在但组件只派发 READY / DATA_READY / CONFIG_CHANGE；`chart-error` 靠内部冒泡 | 评审决定：补齐派发，或从契约中移除两项避免误导 |
| 9.4 | **注入式组件工厂需传框架实例** | 使用方多写一行胶水代码 | 若评审认为体验不足，可增加 `peerDependencies` 版本提供原生组件（会引入版本耦合） |
| 9.5 | **L2 示意数据边界** | 仅 `depth` / `orders` **2 个授权数据集**（`level2-licensed`）需授权；`auction` 为 `l1-intraday-only` 示意、`trades` 已改为运行时派生不落盘；示意数据不能验证与真实市场吻合度 | 产品化时明确数据供应商与合规边界 |
| 9.6 | **`docs/03` 为规划文档** | Rust/WASM、Cargo 工程、`ts-rs` 均未落地，全文用「已确认」措辞 | 已加「方案规划，非当前仓库」注记；评审时勿据此判断当前实现 |
| 9.7 | **历史审计数字** | 两份 HTML 报告 §1–§8 保留当时值（63/63、10 数据集、24 模块等） | 说明卡 / 处置结论已在本轮同步刷新为当前验收数字；历史分节数字保留，以 `docs/00` 与本文为准 |
