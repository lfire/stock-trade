## 一、概念分层总图

```text
Workspace  页面工作台：编排容器 + 全局控件，不做任何空间计算
   │
   ├── Container（容器）         持有渲染介质 / 生命周期 / 事件边界
   │     ├── main-canvas        整体画布（WebGL 单 canvas）
   │     └── detail-canvas      详情画布（DOM 覆盖层）
   │            │
   │            └── Layout（布局）纯数据，容器下唯一的概念
   │                   └── Region（槽位）rect / target / visible / z / constraint
   │                          └── Module（模块）被 Registry 安排到 Region
   │
   ├── Data（数据）              L0 外部输入 → deriveDataset → L1 运行时派生
   │                            L2 授权/示意数据（不可反推，保留）
   │
   └── Algorithms（算法）        18 个纯函数单元，构建期与运行时共用
```

**三条基本原则**

1. **四层正交**：状态（Context）/ 空间（Layout）/ 介质（Container）/ 内容（Module）互不兼任。
2. **单向依赖**：`Module → Region → Layout → Container → Workspace`；反向只允许事件。
3. **单一真源**：同一概念只允许一份实现（常量、算法、口径、布局、数据契约各有一处权威定义）。

## 二、工程与类型层

| 概念 | 定义 | 职责边界（不负责什么） | 代码位置 |
|---|---|---|---|
| **strict TypeScript** | 全量 `strict: true` 标注，`src/` 下 81 个 `.ts` 实现模块 + 1 个手写声明（`global.d.ts`），**0 显式 `any`**、0 隐式 any | 不意味着「运行时有类型检查」；类型只存在于编译期 | `tsconfig.json` |
| **显式 `any` 归零** | 用具体类型 / `unknown` + 单步断言 / `!` 非空断言替代 `any` | `!` 断言编译后擦除，是「保持运行时零改动」的关键手段 | 全仓 |
| **`import type`** | `verbatimModuleSyntax: true` 强制纯类型引用显式标注，编译后完全擦除 | 不产生运行时 import | 全仓 |
| **无扩展名 import + 构建期补全** | 源码统一写 `from '../types'`（不写 `.js`）；tsc 产物**不会补扩展名**，由 `build.mjs` 扫描 `dist/**/*.js` 与 `.d.ts`，把相对 specifier 补成 `.js` 并校验目标存在 | 不是「遗留写法」，是刻意的架构选择；直接去掉 `.js` 或写 `.ts` 都会让 ESM 产物无法加载 | `scripts/build.mjs`、`verify.mjs` 断言 |
| **自动生成声明** | 5 个手写 `.d.ts` 已删除，由 tsc 生成 `dist/**/*.d.ts`；`src/global.d.ts`（JSX / `HTMLElementTagNameMap`）是唯一手写声明，由构建脚本复制进 dist 并在 `dist/index.d.ts` 注入三斜线引用 | 不允许再维护手写声明，避免两套类型漂移 | `src/global.d.ts`、`scripts/build.mjs` |
| **第三方 TS 消费者探针** | 生成临时 strict TS 文件，通过 `npm pack` 的 tarball 安装包，按包名 import 根入口 / `pure` / `react` / `vue` / `events` / 子路径并编译 | 不是单元测试；验证的是**发布包的对外契约** | `scripts/tests/types-consumer.test.mjs` |
| **Bundler / NodeNext** | `moduleResolution: Bundler` 解析无扩展名 import；独立第三方项目另用 `NodeNext` 与 TSX 两种配置交叉验证 | 两者对 `import("..")` 这类目录类型查询的解析不同，曾暴露过 13 个 `TS2307` | `tsconfig.json`、`/tmp/ts-consumer-check` |
| **产物 hash 闸门** | 对 `dist/**/*.js` 剥离注释后计算 SHA-256 快照；类型/架构重构前后必须完全一致，证明运行时零改动 | `.d.ts` 变化属预期，不纳入 hash 闸门 | 各轮重构验证 |
| **`pre*` 脚本** | `predata / precheck / pretest / preserve` 保证任何脚本运行前先构建 | 直接 `node scripts/serve.mjs` **不触发**前置构建，需显式 `npm run build` | `package.json` |
| **pure 子入口** | `stock-chart/pure` 导出几何、指标、聚合、常量、算法注册表 `ALGORITHMS`（18 项）与具名算法函数、架构层，无 DOM / `customElements` 引用 | 根入口在 Node 中因缺 `HTMLElement` 会报错，Node 侧只能用 `pure` | `src/pure.ts` |

| 关联 | 定义 |

## 四、算法层

### 4.1 核心概念

| 概念 | 定义 | 边界 |
|---|---|---|
| **算法单元** | **以算法概念（而非图表/文件职责）为分割单位**的纯 TS 模块：无 DOM、无 IO、无副作用、0 `any` | 不持有状态、不认识 Region、不直接写 dataset |
| **ALGORITHMS 注册表** | 每项登记 `{ id, concept, inputs, outputs, sharedBy, pure }`；`sharedBy` 区分 `runtime` / `build` | 注册表只描述，不调度 |
| **构建期 / 运行时共用** | `scripts/*.mjs` 改为 import `dist/algorithms/*`（薄 re-export），与组件层复用同一实现 | 不再靠 JSON 结果或编译产物间接耦合 |
| **概念统一** | 同一概念只允许一份实现：成交额、均价/VWAP、换手率、涨跌幅基准、取整、时间解析、单位格式化、`trim` | 口径变更须单独立项，不能顺手改 |

### 4.2 18 个算法单元

| 单元 | 概念域 | 主要输入 → 输出 | 共用方 |
|---|---|---|---|
| `rounding` | 价格取整 | number → 分 / 6 位小数（half-up） | runtime + build |
| `random` | 确定性伪随机 | seed → PRNG | build |
| `market-time` | 交易时段 / 时间换算 | `HH:mm` / 周期 → 分钟数、分钟 K 桶、ISO 周 | runtime + build |
| `price-limits` | 涨跌停比例 / 价格 / 四态 | symbol、preClose、rate、Bar → 比例、价、状态 | runtime + build |
| `returns` | 涨跌幅 / 涨跌额 / 振幅 | 价格 + 基准 → 百分比或金额 | runtime + build |
| `vwap` | VWAP / 均价 / 成交额 / 换手率 | 额、量、价、流通股本 → 均价、金额、换手率(%)、增量 | runtime + build |
| `volume-ratio` | 量比（日线 / 分时双口径） | bars、分时点、前 5 日均量 → 比值或曲线 | runtime + build |
| `indicators` | MA / EMA / MACD / KDJ / 副图分发 | K 线序列 + 参数 → 指标序列 + `WARMUP` 预热元数据 | runtime + build |
| `aggregation` | K 线多周期聚合 | bars / intraday / period → `Bar[]` | runtime + build |
| `format` | 单位换算与数值格式化 | number + 单位偏好 → 字符串 | runtime + build |
| `chip-distribution` | 筹码分布估算模型 | bars 近 N 日 + bins/lookback/decay/shape → 9 项统计 + 逐日直方图 | runtime + build |
| `intraday-multi` | 多日分时 | bars、单日 intraday、天数 → 扁平多日序列 | runtime + build |
| `auction-match` | 集合竞价三原则撮合 | 买卖申报价量 + 参考价 → 成交价、匹配量、未匹配量、方向 | runtime + build |
| `auction-series` | 竞价 9 秒节点序列 | bars、intraday、交易日 → open 69 + close 21 | runtime + build |
| `trade-series` | 逐笔明细 | intraday + 交易日 → 按分钟量额严格闭合的逐笔 | runtime + build |
| `depth-snapshot` | 收盘十档快照（示意） | bars + 交易日 → 快照 | runtime + build |
| `order-book` | 委托流生成 / 回放聚合 / 成交关联 | 委托事件、分时曲线、十档 → 事件流、全景簿、逐笔关联 | runtime + build |
| `depth-scenarios` | 普通 / 涨停 / 跌停盘口场景 | 十档、全景、preClose、limitRate → 场景表（不写回输入） | runtime + build |

### 4.3 关键口径速查

| 概念 | 统一口径 | 常见误区 |
|---|---|---|
| **成交额** | 取数据 `amount`；不由 `price × volume` 反推 | 挂单金额是另一概念（`price × volume`），勿混用 |
| **均价 / VWAP** | 均价 = 累计额 / 累计量；当日 VWAP = 当日额 / 当日量（一字板回退四价均） | 二者统计区间不同 |
| **换手率** | 统一为 **%**（`volume / floatShares × 100`） | `profitRatio` / `concentration` 是小数，需 `×100` 显示 |
| **涨跌幅** | `Δ / 基准 × 100`，基准按各交易日昨收（`preCloseByDate`） | 多日模式曾误用首日昨收，导致符号反转 |
| **量比** | 日线 = 当日量 / 前 5 日均量；分时 =（累计量 / 累计开市分钟）÷（前 5 日均量 / 240） | 两套口径分名，共用一个 `avgDailyVolume` |
| **EMA / MACD / KDJ 预热** | EMA 前 n−1 根为 `null`；DEA 只在 DIF 有效段递推；柱 `2×(DIF−DEA)`；KDJ 以 50 起步短窗补齐 | 预热策略由 `WARMUP` 元数据统一描述 |
| **涨跌停** | 板块比例（主板 10% / ST 5% / 创业科创 20% / 北交所 30%）→ `r2(preClose×(1±rate))`，容差 `0.001` 元（远小于 1 tick） | 取整统一 half-up，不用 `toFixed(2)` |
| **撮合三原则** | 最大成交量 → 未成交量最小 → 最接近参考价；候选价含申报价之间 0.01 步长中间价 | 只取申报价并集会漏掉中间价 |
| **委托生命周期** | 每条非 snapshot NEW 必以 FILL 耗尽或 CANCEL 收尾；snapshot 为收盘唯一存活集合 | `openOrders` 上限静默丢弃会破坏守恒 |
| **复权** | 统一前复权 `qfq`，标签由 `manifest.adjust` 动态读取 | 周/月 K `preClose` 取组内首根，分钟 K 取上一根收盘 |
| **成交量单位** | 落盘 `volume` 一律为**股**（东财原生「手」× `LOT_SIZE=100`）；`auction.matchedQty` / `unmatchedQty` 为**手**；`depth.bids/asks[].volume` 为**股** | 市面十档常显「手」，与股差 100 倍；手股换算统一用 `LOT_SIZE`，勿把竞价「手」与成交量「股」相加 |
| **百分数数值与金额** | `turnoverRate` / `pctChg` / `amplitude` 为 **% 数值**（0.33 = 0.33%）；`change` 为元（CNY） | 不是 0~1 小数比例；显示时不再 ×100 |
| **日线时间戳** | `bars.timestamp` 取交易日 **00:00 UTC 毫秒**，由 `tradeDate` 生成 | 非交易所本地开盘时刻，勿用 `new Date()` 反推串日 |

## 六、A 股业务概念

| 概念 | 定义 |
|---|---|
| **集合竞价三原则** | 上交所《交易规则》3.5.2：最大成交量；高于/低于成交价的申报全部成交；同价至少一方全部成交；并列取未成交量最小、再取最接近参考价（可取中间价） |
| **竞价端点锚定** | 9:25 开盘价/量额与 15:00 收盘价/量额由真实行情锚定，中间 9 秒节点为示意 |
| **涨跌停四态** | `limitUp` / `limitDown` / `limitUpBroken` / `limitDownBroken`（封板 / 炸板）；由 close/high/low 与涨跌停价 + `0.001` 容差判定 |
| **十档盘口** | 买 10 / 卖 10 档 `{price, volume, orderCount}`；金额列运行时算 `price × volume` |
| **全景盘口** | 53 买 / 33 卖档，覆盖到涨跌停价；由委托事件流回放聚合，前十档用十档快照覆盖 |
| **盘口场景** | `normal` / `limitUp` / `limitDown`；封单量为示意常量，场景结果不写回原始全景 |
| **逐笔明细** | 交易级记录；`granularity: 'tick' \| 'merged3s'` 区分原生逐笔与公开 3 秒合并分笔，不可混用 |
| **委托生命周期** | `NEW` → `FILL`（可部分成交、按剩余量扣减）/ `CANCEL`（9:20–9:25、14:57–15:00 不可撤）/ 收盘存活 `snapshot` |
| **筹码分布** | 行情软件估算模型（非交易所字段）：三角/均匀成本分布，峰值取当日 VWAP，存量按换手衰减；`COST(50)` 为平均成本，集中度为 `(高−低)/(高+低)` 面板口径（非 SCR 再除 2） |
| **前复权（qfq）** | 历史价格按除权除息调整，`preClose = close − change` 自洽 |
| **交易时段** | 9:30–11:30 / 13:00–15:00 共 240 分钟；`SESSION_MINUTES=120`（每半天）；半小时刻度与 9/14:57 竞价边界为常量真源 |

## 七、术语消解表（旧词 → 新词）

| 旧词 / 旧用法 | 曾经的含义 | 现在的统一含义 |
|---|---|---|
| **pane** | ① Custom Element ② 不可见配置节点 ③ WebGL 裁剪批次 ④ DOM 信息栏 ⑤ 绘图矩形 ⑥ 注册数组 | **Module**（内容单元）；其矩形称 **Region.rect**；`#pane-bars` 称「副图信息栏模块」 |
| **layout** | ① `applyLayout()` ② `layout()` 与 `layout(w,h)` 同名不同类 ③ `LayoutHints` ④ `SubplotLayout` ⑤ `LAYOUT` 行高常量 ⑥ `layout-change` 事件 ⑦ CSS Grid | **Layout** = 空间契约（纯数据 Region 树）；`LAYOUT` 常量只管行高；`LayoutHints` 是 DOM → 布局的输入 |
| **画布 / canvas** | ① `<canvas>` 元素 ② 单 canvas + scissor 架构 ③ 整个 `<stock-chart>` 坐标系 ④「详情画布容器」（其实无 canvas） | **Canvas** 专指 WebGL 元素；整体可视区域称 **main-canvas 容器**；交互详情层称 **detail-canvas 容器** |
| **overlay / cover** | 二者都叫「覆盖层」 | **overlay** = 组件渲染管线内的无交互文本层（`z-index:2`）；**cover** = `DetailCanvasContainer`（`z-index:10`，可交互） |
| **容器** | 只承认 `<stock-chart>` 一个根容器，实际还有 sideSlot / `.chart-card` / `.detail-cover` 四类宿主 | 只有两个正式 **Container**；其余称「模块宿主 / Region 对应 DOM」 |
| **视图 / view** | 数据 `viewport`、UI 视角、虚拟滚动视口、图表模式共用 | **viewport** = 数据索引区间；**view** 只用于虚拟滚动视口；模式用 `ChartMode` / `DetailSet` |
| **模块** | 只指代码组织单元（ES module、`src/algorithms/`） | 代码单元仍称 module；**UI 单元**称 **Module**（注册表项），二者由上下文区分 |
| **三列两行** | 被当作 DOM 结构 | 实为 `MainCanvasLayout` 的 **Region 树**，是 canvas 内像素分区 |
| **SideRect.content** | `'depth'` 在分时表示右列全高、`'chips'` 在 K 线表示右列下半高 | 语义随模式漂移的历史字段；新架构下由 `Region` 的 rect + constraint 明确表达 |
