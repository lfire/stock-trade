> 调研日期：2026-11-14

## 0. 结论先行

1. **行业没有唯一的强制「标准数据格式」**，但存在一个事实标准：每根 K 线 = **OHLCV（`open / high / low / close / volume`）+ 一个时间点 + 一个标的标识**，扩展字段是成交额、昨收、涨跌幅、换手率、复权因子。所有数据源的差异都落在这几个字段的**顺序、单位、类型、时间口径**上。
2. 数据要分三层看，组件只应该依赖中间层：

   | 层 | 谁定义 | 典型形态 |
   |---|---|---|
   | ① 数据源原始格式 | 各数据商 / 网站 | 字符串数组、二维数组、以日期为 key 的对象、列式数组、CSV |
   | ② **归一化数据模型（组件契约）** | 本项目自己定义 | 见第 6 节 `Bar` / `IntradayPoint` |
   | ③ 图表库输入格式 | 图表库 | 见第 5 节，各家互不相同 |

   第 ① 层不通用，第 ③ 层也不通用，所以**必须有一层适配**，且应在数据落库/导出时完成，而不是在 React 组件里反复转换。
3. **「只看历史」这个约束让方案大幅简化**：直接把数据拉下来导出成静态 JSON / CSV 放进前端即可，不需要 WebSocket、轮询、UDF 的 `subscribeBar` / `/stream` / `/quotes` 等实时端点，也不需要行情鉴权中间件。
4. **分时图 ≠ 分钟 K 线**。分时是「每分钟最后成交价 + 均价线 + 每分钟量 + 昨收基准」的折线图；分钟 K 是「每分钟 OHLC + 量」的蜡烛图。两者数据结构不同，不能互相替代。
5. **90% 的适配成本集中在 6 个口径**：字段顺序、时间戳单位与语义、成交量单位、成交额单位、复权方式、昨收基准。本次实测发现同一家（腾讯 vs 东财）的同一分钟成交量，一个是**累计值**、一个是**增量值**，这是最容易踩的坑（见 3.4）。

## 1. 数据分层与「准标准」

虽然没有统一标准，但下面 4 种格式在实际工程中接近「准标准」，值得优先对齐：

| 准标准 | 定义方 | 形态 | 适用场景 |
|---|---|---|---|
| **OHLCV CSV** | 各类数据商通用 | `timestamp,open,high,low,close,volume` 表头 + 每行一根 | 离线数据集、批量导入、最容易人工核对 |
| **TradingView UDF** | TradingView | 列式 `{s, t[], o[], h[], l[], c[], v[]}`，秒级时间戳 | 接 Advanced Charts 图表库时的后端协议 |
| **Lightweight Charts `CandlestickData`** | TradingView | `{time, open, high, low, close}` 对象数组 | 轻量 K 线图组件 |
| **`KLineData`** | KLineCharts | `{timestamp, open, close, high, low, volume?, turnover?}` | 国产 K 线组件，自带指标与画线 |

> 判断：本项目应把「OHLCV CSV + 归一化 JSON」作为**存储/交换格式**，把各图表库的格式当作**运行时适配目标**。

## 2. 市面上能拿到的数据源

### 2.1 免费 / 开源（足够做历史数据与原型）

| 数据源 | 历史日线 | 周/月线 | 分钟 K | 分时 | 复权 | 交易日历 | 返回形态 | 主要限制 |
|---|---|---|---|---|---|---|---|---|
| **东方财富公开 HTTP**（`push2his`） | ✅ 1990 起 | ✅ | 1/5/15/30/60 分钟 | ✅ 单日/多日 | `fqt=0/1/2` | ❌ | JSON 内**逗号分隔字符串数组** | 非官方开放接口，字段靠 `f51~f61` 位序约定；有频率限制 |
| **腾讯证券公开 HTTP**（`web.ifzq.gtimg.cn`） | ✅ | ✅ | 分钟线接口 | ✅ 当日 | `qfq/hfq` 参数 | ❌ | JSON 内**二维数组 / 空格分隔字符串** | 全部为字符串；含盘后固定交易时段 |
| **新浪公开 HTTP** | ✅ 有限条数 | ❌ | 多周期 | 部分 | 多为不复权 | ❌ | 对象数组 | `datalen` 有上限，不适合全量历史 |
| **Tushare Pro** | ✅ 全量 | ✅ | 需积分 | 弱 | `adj_factor` 复权因子 | ✅ `trade_cal` | DataFrame / 表格 | Token + 积分；部分接口付费 |
| **Baostock（证券宝）** | ✅ 1990 起 | ✅ | 5/15/30/60 分钟（无 1 分钟） | ❌ | 不复权/前/后三档 | ✅ | 全字符串 DataFrame | 分钟线历史较短，无实时 |
| **AkShare** | ✅ | ✅ | 1/5/15/30/60 分钟 | 部分 | `qfq/hfq` | ✅ | 中文列名 DataFrame | 本质是上游网页/接口的聚合封装，上游改版会失效 |
| **Alpha Vantage**（海外） | ✅ 25 年+ | ✅ | 1/5/15/30/60 分钟 | ✅ 日内 | `adjusted=true/false` | ❌ | JSON（日期为 key）/ CSV | 免费档 `outputsize=full`、历史 intraday 需付费 |

### 2.2 商业 / 机构级（仅登记，本期不深入）

| 类型 | 代表 | 数据特点 |
|---|---|---|
| 商业 REST API | TickDB、Twelve Data、Polygon.io、阿里云市场「沪深历史 K 线」 | 字段稳定、有 SLA，常见 `{time(毫秒), open, high, low, close, volume, quote_volume, open_interest}`，带 `adjust: none/forward/backward` 参数 |
| 机构终端 | Wind / 同花顺 iFinD / Choice / 聚源 | 覆盖最全（含 L2、逐笔），私有格式，需各自适配 |
| 交易所 Level-2 历史 | 上交所 / 深交所 L2 历史包 | 二进制协议，T+ 延迟，年费量级，需自写解析器 |

> 该表来自二手资料汇总，**具体额度、字段与价格需核实各官方最新文档**，不作为选型结论。

### 2.3 关于「历史分时」的可得性（需要重点确认）

- 日 K / 分钟 K 的历史很充足，**但分时数据的历史深度普遍很浅**：公开接口一般只提供当日或最近几日（东财 `trends2` 用 `ndays` 控制，腾讯 `minute/query` 只给当日）。
- 若产品要「回看任意历史某一天的分时图」，通常做法是**用该日的 1 分钟 K 线还原分时**（取每分钟 close 作为价格点，累计 amount / 累计 volume 算均价），而不是依赖分时接口。
- 因此**分钟 K 的历史覆盖深度，比分时接口本身更关键**；而免费源对 1 分钟线的历史覆盖普遍有限（Baostock 无 1 分钟线，Tushare 需积分，AkShare 取决于上游）。这一点建议在下期做专门的可行性验证。

## 3. 真实数据样例逐条拆解（一手实测）

> 下列样例均由本次调研直接请求公开接口取得，抓取时间 2026-11-14，标的统一为贵州茅台 `600519`（`secid=1.600519` / `sh600519`），仅用于说明数据结构。

### 3.1 东方财富 · 历史日 K（JSON + 字符串数组）

请求：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get
  ?secid=1.600519&fields1=f1,f2,f3,f4,f5,f6
  &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
  &klt=101&fqt=1&beg=20240102&end=20240110
```

返回（节选，来源：东方财富 `push2his`，抓取于 2026-11-14）：

```json
{
  "rc": 0,
  "data": {
    "code": "600519", "market": 1, "name": "贵州茅台", "decimal": 2,
    "dktotal": 6042, "preKPrice": 1591.66,
    "klines": [
      "2024-01-02,1580.66,1550.67,1583.85,1543.76,32156,5440082548.00,2.52,-2.58,-40.99,0.26",
      "2024-01-03,1546.77,1559.66,1560.88,1541.99,20229,3411400667.00,1.22,0.58,8.99,0.16"
    ]
  }
}
```

`klines` 每项是**逗号分隔的字符串**，字段位序由 `fields2` 决定：

| 位序 | 字段 | 含义 | 单位 / 类型 |
|---|---|---|---|
| 1 | 日期 | 交易日 | `YYYY-MM-DD` |
| 2 | 开盘 | `open` | 元，字符串 |
| 3 | 收盘 | `close` | 元，字符串 |
| 4 | 最高 | `high` | 元，字符串 |
| 5 | 最低 | `low` | 元，字符串 |
| 6 | 成交量 | `volume` | **手**，字符串 |
| 7 | 成交额 | `amount` | 元，字符串 |
| 8 | 振幅 | `amplitude` | % |
| 9 | 涨跌幅 | `pct_chg` | % |
| 10 | 涨跌额 | `change` | 元 |
| 11 | 换手率 | `turnover_rate` | % |

> ⚠️ 顺序是 **日期 / 开 / 收 / 高 / 低**，既不是 OHLC，也不是 ECharts 的 OCLH。直接按「开高低收」解析会画出完全错误的 K 线。
> 周期参数 `klt`：`1`=1 分钟、`5`/`15`/`30`/`60`=分钟、`101`=日、`102`=周、`103`=月；复权 `fqt`：`0` 不复权、`1` 前复权、`2` 后复权。

### 3.2 东方财富 · 分时（JSON + 字符串数组）

请求：

```
https://push2his.eastmoney.com/api/qt/stock/trends2/get
  ?secid=1.600519&fields1=f1,f2,f3,f4,f5,f6,f7,f8
  &fields2=f51,f52,f53,f54,f55,f56,f57,f58&ndays=1&iscr=0
```

返回（节选，来源：东方财富 `push2his`，抓取于 2026-11-14）：

```json
{
  "data": {
    "code": "600519", "name": "贵州茅台", "decimal": 2,
    "preClose": 1410.27,
    "trends": [
      "2026-11-13 09:30,1404.00,1404.00,1404.00,1404.00,150,21060000.00,1404.000",
      "2026-11-13 09:31,1403.10,1397.51,1403.10,1394.00,714,99787636.00,1398.700",
      "2026-11-13 09:32,1397.28,1401.85,1401.85,1397.28,308,43119786.00,1399.039"
    ]
  }
}
```

单项结构（`fields2=f51~f58`）：

| 位序 | 字段 | 含义 | 说明 |
|---|---|---|---|
| 1 | 时间 | `YYYY-MM-DD HH:mm` | 市场本地时间 |
| 2 | 开 | 该分钟开盘价 | 分时折线一般不用 |
| 3 | **收 / 最新** | 该分钟最后成交价 | **分时价格线用这个** |
| 4 | 高 | 该分钟最高 | 可选 |
| 5 | 低 | 该分钟最低 | 可选 |
| 6 | 成交量 | **该分钟增量** | 手 |
| 7 | 成交额 | **该分钟增量** | 元 |
| 8 | 均价 | `avg_price` | 累计额 ÷ 累计量 |

顶层 `data.preClose` 是**昨收价**，分时图的零轴、涨跌幅右轴、涨跌颜色全靠它。

### 3.4 腾讯证券 · 分时（空格分隔字符串，**累计量额**）

请求：`https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600519`

返回（节选，来源：腾讯证券，抓取于 2026-11-14）：

```json
{
  "data": {
    "sh600519": {
      "data": {
        "date": "20261113",
        "data": [
          "0930 1404.00 150 21060000.00",
          "0931 1397.51 864 120847636.00",
          "0932 1401.85 1172 163967422.00",
          "0933 1402.02 1384 193660164.00"
        ]
      }
    }
  }
}
```

单项结构：`HHmm 最新价 累计成交量(手) 累计成交额(元)`，**只有 4 个字段，没有均价字段**。

本次实测统计（`sh600519` / 2026-11-13）：

| 项目 | 实测值 |
|---|---|
| 总点数 | 267 |
| 上午 09:30–11:30 | 121 点 |
| 下午 13:00–15:00 | 121 点 |
| 常规交易时段合计 | **242 点** |
| 盘后 15:01–15:30 | 25 点 |

**与东财数据的交叉验证（同一天同一标的）**：

| 验证项 | 结果 |
|---|---|
| 价格序列 | 两边完全一致：`1404.00 / 1397.51 / 1401.85 / 1402.02 …` |
| 量的口径 | 腾讯 09:31 累计量 `864` = 东财 09:30 `150` + 09:31 `714` → **腾讯是累计、东财是增量** |
| 均价公式 | 腾讯 09:31 `120847636 ÷ (864 × 100) = 1398.699`，与东财 `avg_price=1398.700` 一致 → **`均价 = 累计成交额 ÷ (累计成交量 × 100)`，成交量单位为「手」** |

> 这两条是本调研最关键的结论：**均价不是价格的算术平均**，且不同数据源的「量」可能一个是增量、一个是累计。归一化时必须显式声明并统一。

```json
  },

      "3. low": "244.8300",
      "4. close": "247.1300",
      "5. volume": "2669242"
    }
  }

```

CSV（`datatype=csv`，来源同上）：

```csv
timestamp,open,high,low,close,volume
2026-11-13,246.6300,247.8500,244.8300,247.1300,2669242
2026-11-12,248.3000,248.7700,244.3700,244.6700,2816978
```

日内（`TIME_SERIES_INTRADAY`）返回结构相同，只是 key 变成 `"2026-11-13 19:55:00"`，并带 `Interval`、`Output Size`、`Time Zone` 元数据。

官方参数要点（来源：Alpha Vantage 官方文档，2026-11-14）：

- `interval`：`1min / 5min / 15min / 30min / 60min`
- `adjusted`：默认 `true`（历史拆股/分红调整），`false` 为原始成交价
- `extended_hours`：默认 `true`，含盘前盘后；美股常规时段需设 `false`
- `month=YYYY-MM` + `outputsize=full` 可查历史某月 intraday；`compact` 仅最近 100 点
- `datatype=json|csv`；`outputsize=full` 的 25 年全量需付费档

> 这是「海外标准数据」最典型的样子：**以时间字符串为 key 的对象 + 带序号前缀的字段名 + 全部字符串数值 + 独立 Meta Data 块声明时区**。

### 3.7 Tushare Pro（表格型，单位陷阱最多）

`daily` 日线行情（来源：Tushare Pro 官方文档，2026-11-14）：

| 字段 | 含义 | 单位 / 口径 |
|---|---|---|
| `ts_code` | 股票代码 | `000001.SZ` 形式 |
| `trade_date` | 交易日期 | `YYYYMMDD` 字符串 |
| `open / high / low / close` | OHLC | 元，**未复权** |
| `pre_close` | 昨收价 | **除权价** |
| `change / pct_chg` | 涨跌额 / 涨跌幅 | 元 / %（基于除权昨收） |
| `vol` | 成交量 | **手** |
| `amount` | 成交额 | **千元**（不是元！） |

官方明确：`daily` 是未复权行情，**停牌期间不提供数据**；交易日 15:00–16:00 入库。

配套数据：

- `adj_factor` 复权因子：`{ts_code, trade_date, adj_factor}`，盘前 9:15–9:20 入库（来源：Tushare Pro 官方文档，2026-11-14）。
- `trade_cal` 交易日历：`{exchange, cal_date, is_open(0休市/1交易), pretrade_date}`（来源：Tushare Pro 官方文档，2026-11-14）。

> 前复权 / 后复权的常见换算（行业通用做法，**具体实现需以所选数据源口径为准**）：
> `后复权价 = 原始价 × 当日 adj_factor`；`前复权价 = 原始价 × 当日 adj_factor ÷ 最新 adj_factor`。
> 前复权会使历史价随新的除权事件变化，因此**同一序列必须锁定单一主源、单一复权口径**。

### 3.8 Baostock（官方字段）

`query_history_k_data_plus` 日线字段（来源：Baostock 官方文档，经检索结果引用，2026-11-14）：

`date, code, open, high, low, close, preclose, volume, amount, adjustflag, turn, tradestatus, pctChg, isST`

- `volume` 单位为**股**，`amount` 单位为**元**，价格精确到小数点后 4 位，**返回值全为字符串**。
- 分钟线字段不同：`date, time, code, open, high, low, close, volume, amount, adjustflag`，其中 `time` 格式 `YYYYMMDDHHMMSSsss`，`volume/amount` 是该时间范围内的**累计值**。
- `adjustflag`：`1` 后复权 / `2` 前复权 / `3` 不复权。

### 3.9 TradingView UDF `/history`（列式，后端协议标准）

来源：TradingView Advanced Charts 官方文档（2026-11-14）：

```json
{
  "s": "ok",
  "t": [1386493512, 1386493572, 1386493632, 1386493692],
  "c": [42.1, 43.4, 44.3, 42.8],
  "o": [41.0, 42.9, 43.7, 44.5],

```

要点：

- 「response-as-a-table」**列式**结构，不是行式对象数组；`s` 状态可取 `ok / error / no_data`，`no_data` 时用 `nextTime` 指向最近一根可用 bar。
- `t` 为 **UTC 秒级**时间戳；官方明确规定日线 bar 时间取交易日的 `00:00 UTC`，月线取当月首个交易日的 `00:00 UTC`。
- **价格必须是 number，不能是字符串**。
- UDF 端点：`/config`、`/symbol_info`、`/search`、`/symbols`、`/history`、`/marks`、`/timescale_marks`、`/time`、`/quotes`。纯历史场景只需 `/config` + `/symbol_info`(或 `/symbols`) + `/history`。

## 5. 前端图表库要求的数据结构（第 ③ 层）

| 图表库 | K 线数据 | 时间字段 | 成交量 | 关键点 |
|---|---|---|---|---|
| **Lightweight Charts 5.3**（TradingView） | `{time, open, high, low, close}`，可选 `color / borderColor / wickColor / customValues` | `Time = UTCTimestamp(秒) \| BusinessDay{year,month,day} \| 'YYYY-MM-DD'` | 独立 `HistogramSeries`：`{time, value}` | 数据必须**严格按时间升序**；不能传 `Date` 对象；日期字符串必须是零填充 `YYYY-MM-DD`；Apache-2.0，但**要求保留 TradingView 署名** |
| **KLineCharts v10** | `KLineData = {timestamp, open, close, high, low, volume?, turnover?}` | `timestamp` 为**毫秒** | `volume` 内置 | 所有字段必须是 **number**；`turnover` 是 EMV/AVP 指标所需；`setDataLoader({getBars, subscribeBar, unsubscribeBar})` 中 **`getBars` 可单独实现**，`subscribeBar` 可省略 → **非常适合纯历史场景** |

| **TradingView Advanced Charts (UDF)** | 列式 `t/o/h/l/c/v` | UTC **秒** | `v[]` | 需后端实现 `/config`、`/symbol_info`、`/history` 等；仅历史时可不实现 stream/quotes |
| **HQChart** | 分时 / K 线各有专有结构 | 分时 `time` 有 `'09:30'` 与 `930` 两种写法 | 内置 | 国内看盘场景常用；**该条来自二手资料，具体格式需核实官方示例** |

## 6. 建议的组件内部统一数据模型

> 本节为第一期建议契约；当前实现见 `src/types.ts`，当时建议的 `src/types/market.ts` 不存在

组件不要直接吃数据源格式，而是约定下面这份契约（可直接放进 `src/types/market.ts`）：

```ts
type Interval = '1m' | '5m' | '15m' | '30m' | '60m' | '1d' | '1w' | '1M';
type Adjust = 'none' | 'qfq' | 'hfq';

/** 一根 K 线：所有单位已归一化 */
interface Bar {
  timestamp: number;        // UTC 毫秒，统一表示 bar 的起始时刻
  tradeDate: string;        // 'YYYY-MM-DD'，市场本地交易日，避免前端 new Date 造成跨时区偏移
  open: number;
  high: number;
  low: number;
  close: number;
  preClose: number;         // 昨收；复权口径须与上面四个价格一致
  volume: number;           // 统一为「股」
  amount: number;           // 统一为「元」
  turnoverRate?: number;    // %
  adjFactor?: number;       // 保留原始因子，便于随时切换复权
  rawClose?: number;        // 保留未复权收盘价，用于校验
}

/** 一个分时点：量额统一为「该分钟增量」 */
interface IntradayPoint {
  timestamp: number;        // UTC 毫秒
  time: string;             // 'HH:mm'，市场本地
  price: number;            // 该分钟最后成交价
  avgPrice: number;         // 累计额 ÷ 累计量，不是价格算术平均
  volume: number;           // 该分钟增量，股
  amount: number;           // 该分钟增量，元
}

interface ChartDataset {
  symbol: string;           // 建议 '600519.SH' 形式
  market: 'CN' | 'HK' | 'US';
  currency: 'CNY' | 'HKD' | 'USD';
  timezone: string;         // 'Asia/Shanghai'
  interval: Interval;
  adjust: Adjust;
  preClose: number;         // 分时图零轴基准
  session: { open: string; close: string }[];  // 交易时段，如 09:30-11:30 / 13:00-15:00
  bars?: Bar[];
  points?: IntradayPoint[];
  source: string;           // 数据血缘
  updatedAt: string;        // ISO 8601
}
```

适配层（伪代码，示意字段映射，非完整实现）：

```ts
// 东财 klines -> Bar：注意 O,C,H,L 位序 + 手转股
const [d, o, c, h, l, vol, amt, amp, pct, chg, turn] = line.split(',');
bar = { open: +o, close: +c, high: +h, low: +l, volume: +vol * 100, amount: +amt, ... };

// Bar -> Lightweight Charts：毫秒转秒
candles = bars.map(b => ({ time: (b.timestamp / 1000) as UTCTimestamp,
                           open: b.open, high: b.high, low: b.low, close: b.close }));

// Bar -> ECharts：按 OCLH 重排；成交量另起一个 series
candleData = bars.map(b => [b.open, b.close, b.low, b.high]);

// Bar -> KLineData：毫秒，字段名 turnover
klineData = bars.map(b => ({ timestamp: b.timestamp, open: b.open, close: b.close,
                             high: b.high, low: b.low, volume: b.volume, turnover: b.amount }));

// Bar[] -> UDF /history：列式 + 秒
udf = { s: 'ok', t: bars.map(b => b.timestamp / 1000), o: ..., h: ..., l: ..., c: ..., v: ... };
```

## 7. 「只看历史」的落地建议

> 以下为当时设想，现状由 manifest 5 键（`bars`/`intraday`/`auction`/`depth`/`orders`）驱动、逐笔运行时派生

1. **交付形态用静态文件即可**：把数据预导出为 `/public/data/{symbol}/{interval}.json`（或 OHLCV CSV），组件按 `symbol + interval + date` 加载，无需后端、无需 WS、无需行情鉴权。
2. **文件级元数据不可省**：每个文件带 `symbol / market / timezone / interval / adjust / preClose / session / source / updatedAt`，否则跨市场、跨复权口径一定出错。
3. **数据量估算**（按 A 股约 242 交易日/年、240 分钟/日推算，属估算值）：
   - 单只股票 20 年日线 ≈ 4,840 根，JSON 约数百 KB；
   - 单只股票 1 年 1 分钟线 ≈ 242 × 240 ≈ 5.8 万根，5 年 ≈ 29 万根 → 建议按年分片、按需加载；
   - 单只股票单日分时 = 242 点（常规时段），极小，可整日存放。
4. **交易日历**：把 `is_open` 日历或「交易日列表」一起导出，前端用 category 轴按交易日渲染，避免周末/节假日空档；停牌日直接不出现在序列中（Tushare `daily` 明确停牌无数据）。
5. **复权**：建议存「未复权 OHLC + `adjFactor`」，复权在导出时按 `adjust` 参数生成三份文件或按需计算；**绝不混用两个数据源的价格与因子**。
6. **分时历史**：优先用 1 分钟 K 线还原（见 2.3），并在 `ChartDataset.session` 中声明交易时段，午休不插点。
7. **合规**：公开接口多为非正式开放接口，仅适合个人研究/原型；产品化对外展示行情前需确认数据源授权，商业展示通常另需行情授权。

## 8. 坑点 Checklist（接入前逐条核对）

| # | 坑 | 实测依据 |
|---|---|---|
| 1 | 字段顺序不是 OHLC | 东财/腾讯是 **O,C,H,L**；ECharts 要 **O,C,L,H**；新浪/Alpha Vantage 是 **O,H,L,C** |
| 2 | 成交量单位差 100 倍 | 东财/腾讯/Tushare 是「手」，新浪/Baostock 是「股」 |
| 3 | 成交额单位不统一 | 东财/新浪是「元」，**Tushare `daily` 是「千元」** |
| 4 | 数值全是字符串 | 东财/腾讯/新浪/Alpha Vantage/Baostock 均返回字符串，图表库多要求 `number`（UDF 明确禁止字符串价格） |
| 5 | 时间戳单位三种 | UDF / Lightweight Charts = **秒**，KLineCharts = **毫秒**，其余多为日期字符串 |
| 6 | 分时量额「累计 vs 增量」 | 腾讯 `minute` 是累计，东财 `trends2` 是增量（864 = 150 + 714 已验证） |
| 7 | 均价算法错误 | `avg = 累计额 / (累计量 × 100)`，不是价格算术平均（已与东财 `avg_price` 对拍验证）。**注：此处为数据源以「手」计量时的口径；本工程当前 `units.volume = share`（股），均价 = 累计额 ÷ 累计量，见 `docs/00` §4.3** |
| 8 | 昨收基准缺失 | 分时零轴必须带 `preClose`；Tushare 的 `pre_close` 是**除权价** |
| 9 | 交易时段口径不一致 | 腾讯当日分时 267 点 = 常规 242 + 盘后 25；美股本盘前盘后需 `extended_hours=false` 才排除 |
| 10 | 复权口径混用 | 前复权历史价会随新除权事件变化，跨源对比会失真 |
| 11 | 停牌 / 节假日断档 | 图表库不处理，需交易日历 + category 轴 |
| 12 | 日期被 `new Date()` 解析偏移 | `YYYY-MM-DD` 字符串在 UTC+8 环境下可能串日，日线务必保留纯字符串 `tradeDate` |
