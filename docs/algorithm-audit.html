结论：目前不能满足「算法不偏差、不出错」

组件化工程做得很扎实，但由原始数据计算得出的指标里有 3 处与通达信 / 同花顺 / 上交所口径存在可量化的实质偏差，另有 4 处口径或命名错位、1 处校验方法缺陷。KDJ、MACD 柱倍率、均价线 VWAP、周月聚合、交易时段等主体部分是正确的。

  • 阻断 EMA 首值冷启动 + 无预热期：MACD 前段 DIF 与标准口径符号相反，有效段最大偏差 15.44；默认视口正好落在偏差区。
  • 阻断 量比用日线口径：盘中 09:35 标准值 2.4691，组件恒为 1.2823；仅收盘恰好相等。
  • 阻断 分钟 K 按序号分组：5m / 30m / 60m / 120m 各有 1 根跨 11:30–13:00 午休。
  • 重要 筹码三角分布峰值假设、平均成本命名错位、涨跌停 0.5% 容差与固定 ±10%、竞价虚拟价未按最大成交量原则撮合。
  • 披露 筹码 / 竞价 / 逐笔 / 十档 / 委托流全为固定种子合成数据，不能用于验证与真实 A 股市场的吻合度。

一、核验方法

  • 源码盘点：逐文件摘录每个派生量的公式、初值、边界、参数与文件行号，区分「运行时从 OHLCV 计算」与「生成阶段写入 JSON 只读」。
  • 外部口径核实：按金融场景检索路由，用多源检索核对通达信 / 同花顺递推算法、上交所 / 深交所交易规则、筹码分布模型与集中度定义。
  • 独立数值复算：不复用项目实现，另写一套标准口径公式，喂入项目真实日 K / 分时数据，逐根比对偏差。

口径分歧的三个高频点（已逐项确认）：EMA 初值须 SMA 初始化、通达信 SMA(X,N,M) 不是算术平均而是 Y=(M·X+(N−M)·Y')/N、MACD 柱国内乘 2 而欧美不乘。

3.4 涨跌停判定容差

以 eps = preClose × 0.005（0.5%）复核 935 根日 K：命中 4 根，其中 2 根收盘价并不等于四舍五入后的涨跌停价，属于潜在误标。前复权数据下正确做法是「按前复权昨收 ×(1±比例) 四舍五入到 0.01 元」并允许约 0.01 元量级误差，而非 0.5% 相对容差。当前示例标的 600519.SH 属沪市主板，±10% 恰好正确；但组件未做板块识别，遇到创业板 / 科创板 / ST / 北交所会算错。

筹码分布本身是估算模型（交易所不公开持仓成本）；通达信 / 同花顺在衰减系数、日内分布、分桶精度、复权方式上参数不同，跨软件出现零点几个百分点差异属建模差异而非 bug。本组件集中度公式与同花顺面板口径一致（不除 2），若与通达信 SCR 指标对照需再除 2。
