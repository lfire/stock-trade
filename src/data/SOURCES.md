## 真实公开数据（已尝试并成功采集）

日 K：东方财富 push2his kline（fqt=1 前复权）真实数据 936 根，剔除 2026-11-13 之后未完成的当日 K 线，保留 935 根。
涨跌停状态：按代码/名称识别板块确定比例（本例 600519.SH 沪市主板 10%），涨跌停价 = 前复权昨收 ×(1±比例) 四舍五入到 0.01 元，容差固定 0.011 元（1 个最小变动单位），不再用 0.5% 相对容差；真实序列里涨停仅 1 根、跌停与跌停炸板为 0，故在中段 4 个交易日拟真注入 涨停 / 跌停 / 涨停炸板（触板未封住）/ 跌停炸板（触板未封死）各 1 根，仅调整这 4 根 OHLC 及其派生字段并同步下一根 preClose 链条，保证四种配色在图上均可见。
分时：腾讯 minute/query 在 2026-11-13 的真实完整交易日数据 267 点（上午 121 + 下午 121 + 盘后 25）。腾讯返回累计量额，已差分为每分钟增量并按「累计额 ÷ (累计量 × 100)」还原均价。
集合竞价：历史交易日的 9:15–9:25 虚拟撮合快照属 Level-2 数据，免费公开接口无法回溯（AkShare / Tushare / Baostock / 聚宽 / 米筐 / 券商 L1 在该窗口均返回空；仅当日可通过 AKShare MCP get_stock_auction_tool 或通达信协议 get_call_auction 拉取后自行归档）。因此本数据为**锚定真实值 + 按上交所《交易规则》3.5.2 三原则撮合的示意委托簿**：虚拟撮合价 / 匹配量 / 未匹配量 / 方向全部由 `matchAuction()` 按「最大成交量 → 未成交量最小 → 最接近前收」算出，不再硬编码阶梯价或随机方向；委托簿为集中在撮合价的示意簿（L2 逐笔委托无法回溯）。①真实锚点取同一交易日的昨收 1410.27、9:25 开盘价 1404.00、9:25 集合竞价成交量/额（= 分时 09:30 首点 15000 股 / 21060000 元 = 150 手），末点与真实值精确闭合；②按同花顺终端口径生成 69 个 9 秒节点（9:15:00–9:25:00，9:19:57→9:20:00 与 9:24:57→9:25:00 各 3 秒）；③拟真行为：价格只在少数节点跳变形成长水平段（9:15 虚假买单托高 → 9:19:57 集中撤单跳水 → 9:20 后不可撤单缓慢收敛 → 9:25 真实开盘价）、虚拟匹配量单调不减且后期加速、未匹配量撤单后跳降并衰减到 0、可撤单期买方堆积(红)为主后转卖方堆积(绿)；④仅 9:25 产生成交量，其余节点「价有量无」。
尾盘竞价（收盘集合竞价 14:57–15:00）：上交所 2018-08-20 起对股票实施 3 分钟收盘集合竞价，可申报不可撤单、行情揭示同开盘集合竞价。历史虚拟撮合快照同样属 L2 无法回溯，故与开盘竞价一致采用**锚定真实 + 三原则撮合的示意委托簿**（并列价参考最近成交价 14:57 末价）：①真实锚点取 14:57 连续竞价末价 1434.52、15:00 收盘价 1435.26（= 日 K close）、15:00 集合竞价成交量 177300 股 / 254471605.07 元 = 1773 手，末点精确闭合；②按同花顺终端口径生成 21 个 9 秒节点（14:57:00–15:00:00）；③真实分时里 14:58/14:59 成交量为 0（价有量无），仅 15:00 统一撮合有量；④不可撤单期虚拟匹配量单调不减、未匹配量逐步被吸收到 0、买方堆积(红)为主。

## 原始数据留档

`src/data/raw/` 保存抓取到的原始响应，便于复核字段与单位；`scripts/fetch-public-data.mjs` 可重跑。

## 单位与口径

- 价格：元；成交量：**股**（东财返回「手」，已 ×100）；成交额：元。
- 时间戳：UTC 毫秒；`tradeDate` / `time` 保留市场本地字符串，避免 `new Date()` 串日。
- 复权：前复权（qfq）；`preClose = close - change`，与前复权涨跌额自洽。
- 分时均价：`累计成交额 / (累计成交量(手) × 100)`，不是价格算术平均。
- 集合竞价期间成交量为 0，仅 9:25 统一撮合有量；集合竞价成交方向为 `N`（无主动方向）。
