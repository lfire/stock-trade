## 股票图表组件 · 扩展数据类型与 Level2 调研（第二期）

- 用户补充需求：组件要含主图 + 多副图（成交量/成交额/量比/MACD 等），并支持筹码峰、集合竞价、交易明细（Level2，含 B/S/C），仍以查看历史为目标。
- 产出：`docs/02-扩展数据类型与Level2调研.md`（445 行），承接第一期，含需求→数据依赖矩阵、副图指标计算输入、筹码峰两种数据形态、集合竞价一手字段、Level2 CSV/STEP 字段、B/S/C 完整对照表、扩展 TS 数据模型、组件 pane 架构影响、16 条坑点、来源分级。
- 核心结论 A：11 个副图里 7 个只需 OHLCV（MACD/KDJ/RSI/BOLL/OBV 等前端算即可）；真正需要新增数据的只有量比（前 5 日分钟量）、换手率（流通股本）、资金流（逐笔 BS）、筹码峰、集合竞价、逐笔明细、十档盘口。
- 核心结论 B：筹码峰不是交易所 L2 字段、无官方标准格式，是三角形成本分布建模估算；只有「按日统计指标（获利比例/平均成本/90、70 成本区间与集中度）」和「150 档 prices[]+ratios[] 直方图」两种形态。
- 核心结论 C（B/S/C 不是统一字段）：沪市成交 TradeBSFlag = B/S/N（2021-04-26 起，N 交易所原文为「未知」）；沪市委托 OrderBSFlag = B/S，撤单是 OrdType='D' 不是 C；深市成交 ExecType = 4撤单/F成交、Side = 1/2/G/F，无主动性字段；通达信深市委托标识串里 C = 撤单记录；集合竞价成交交易所不打 BS。
- 一手实测（sh600519，2026-11-15）：东财 `details` 返回 `时间,价,量(手),笔数,方向码(1/2)` 的 3 秒合并分笔，含盘后 15:05–15:30，收盘竞价 15:00:02 标 1；腾讯 `detail` 返回 `序号/时间/价/涨跌/量/额/BS`，用 B/S/M（M 中性），70 条分布 S26/M24/B20，09:25:02 集合竞价被标 S。两家对竞价与中性盘的编码不同，证明必须保留 rawSide + sideSource。
- 数据量：DolphinDB 二手资料给出逐笔委托单日约 12GB、逐笔成交约 6GB、全 A 高频每日 30GB+；前端必须按 symbol×tradeDate 分片、服务端预聚合、明细分页 + 虚拟滚动。
- 集合竞价：上交所 Auction.csv 字段 SecurityID/DateTime/Price/VirtualAuctionQty/LeaveQty/Side(0/1/2)，仅 2018-12-24 前，之后在 Snapshot.csv；PhaseCode 第 1 位 C=集合竞价；AkShare 盘前分时 09:15 起竞价期间成交量为 0、价格是虚拟撮合价，且只返回最近一个交易日。

## 股票图表组件 · 架构与 Rust 性能方案设计（第三期）

- 用户要求：自行实现 1 个以上 Web 组件，统一考虑前两期所有数据结构与需求，性能相关部分用 Rust 实现，给出设计方案。
- 产出：`docs/03-组件架构与Rust性能方案设计.md`（411 行），含 8 条关键决策、约束回溯、五层架构、组件拆分与 API、统一数据结构落位、Rust/TS 职责边界、列式内存模型、数据流与 Worker 拓扑、性能预算、工程结构、P0–P4 路线、10 项风险、8 个待确认决策点、来源分级。
- 关键决策：Web Components（Custom Elements）为外壳 + 自研 Canvas2D 渲染器（不依赖 ECharts/TradingView/KLineCharts，前期图表库契约仅作字段参考）；Rust→WASM 跑在 Web Worker，主线程只做 DOM/事件/调度；列式 SoA TypedArray 存 WASM 线性内存并导出 ptr+len 零拷贝视图；7 个组件（P0 三个：stock-chart / price-pane / indicator-pane；P2 加 chip-pane / auction-pane；P3 加 trade-tape / depth-book）；多线程为可选增强，默认单线程 + SIMD128 + 分帧；静态分片 + 构建期预计算；Rust 结构体为类型唯一真源，ts-rs/typeshare 生成 TS 类型。
- 组件通信：根容器持有 ChartContext（viewport / priceScale / crosshairIndex / theme / store / wasm），viewport 单一真源，crosshair-change CustomEvent 按同一 index 广播，避免 props 层层传。
- 渲染性能：Rust 生成 `#[repr(C)] DrawCommand` 紧凑数组，JS 批量回放（Canvas2D）；WebGL2 后端由 Rust 直填顶点 buffer 一次 draw call；禁止逐条跨边界调 Canvas API 或传 String，统一 `&[u8]` + ptr/len。
- 一手核实：MDN SharedArrayBuffer 确认 SAB 需安全上下文 + 跨源隔离（COOP: same-origin / COEP: require-corp），`WebAssembly.Memory({shared:true})` backing 是 SAB，`Atomics.wait` 不能在主线程；js-sys `Float64Array::view` 零拷贝视图在 WASM 内存 grow 后失效 → 方案约定加载期预分配固定容量。
- 二手资料（需核实）：wasm-bindgen-rayon / build-std+atomics 多线程配置、min/max 与 LTTB 降采样范式、release 构建性能差异、ts-rs 等工具建议。所有性能数字均标注为设计估算，P4 需实测。
- 待用户确认：组件形态（Web Components vs 纯 React）、渲染后端（Canvas2D vs 直接 WebGL2）、部署能否设 COOP/COEP、L2 数据来源与授权、筹码峰是否需历史回放、是否要 SSR、浏览器基线、主题与涨跌颜色。
