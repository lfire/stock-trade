## 二次确认：部署环境可设置 COOP/COEP → 启用 WASM 多线程

- 用户后续确认部署环境**可以支持 COOP/COEP**，方案从「单线程唯一路径」改为「**多线程可用 + 双构建自动降级**」；`docs/03-…` 从 588 → 695 行。
- 一手核实 `wasm-bindgen-rayon` 官方 README：线程版需固定 nightly（README 测试版 `nightly-2025-11-15`）+ `rust-src`；`.cargo/config.toml` 配 `+atomics,+bulk-memory`、`--shared-memory`、`--max-memory=1073741824`（1GB 固定上限）、`--import-memory`、四个 TLS 导出符号、`[unstable] build-std=["panic_abort","std"]`；必须 `wasm-pack build --target web`；运行时 `initThreadPool(n)`。官方明确建议**两份构建 + `wasm-feature-detect.threads()` 特性检测**，因为带 atomics 的 WASM 在不支持环境无法实例化。bundler 推荐 Vite。
- Worker 拓扑：主线程（DOM/GL）→ Layer1 主计算 Worker（1 个，保护 UI）→ Layer2 rayon Worker 池（N 个，`min(hardwareConcurrency, 8)`）；GL 提交仍在主线程，多线程只加速 Worker 内计算。
- 部署清单：Nginx `COOP: same-origin` + `COEP: require-corp`（带 `always`）、HTTPS、第三方资源需 CORP/CORS、iframe 父页面同设；Vite 的 `server` 与 `preview` 都要配头。验证 `crossOriginIsolated` + `typeof SharedArrayBuffer` + 新增 `compute-mode-change` 事件。降级到 `pkg-single` 功能一致，带 `reason`。
- 关键工程判断（§6.4 并行性分析）：**不是所有计算都能并行**。可并行 = 多标的批量解析/指标、多副图不同指标、min/max 降采样、L2 逐笔按桶分片聚合、筹码峰多标的预计算；**串行 = EMA/MACD/KDJ/RSI 递推、筹码逐日衰减**；累计量额/均价需并行前缀扫描；WebGL 提交主线程专属。要求线程版与单线程版逐字段对拍，禁止无脑 `par_iter`。
- shared memory 固定 1GB 上限且 grow 会使视图失效 → 强化「加载期预分配固定容量」约定；`pkg-threads/` + `pkg-single/` 双产物按需动态 import，只加载一份。
- 路线调整：P1 引入双构建与并行化（验收为两版结果一致），P4 做多线程压测、线程数调优、降级路径与部署头审计。

## 黑屏故障排查与修复

- 用户反馈运行后黑屏。用无头 Chrome（`--headless=new --enable-unsafe-swiftshader --use-angle=swiftshader`）截图 + `--enable-logging=stderr` 抓控制台，定位到 `chart-context.js:62`：`Uncaught TypeError: Cannot read properties of null (reading 'bars')`。
- 根因：`<stock-chart>` 的 connectedCallback 在**数据加载之前**调用 `setMode(mode)` → `resetViewport()` → `getSeries()` 读 `this.dataset.bars`，dataset 仍为 null 抛异常，直接中断 connectedCallback，导致其后的 `loadDataset()` **从未执行**；同时 `ChartContext.render()` 在 dataset 为 null 时直接 return，WebGL canvas 从未 clear（默认黑底）→ 黑屏 + 「示例数据」永远停在「加载中…」。
- 修复（5 处）：
  1. `getSeries()` 对 `dataset === null` 返回 `[]`；setMode/panBy/zoomBy 在数据前调用不再崩。
  2. connectedCallback 改为只赋 `ctx.mode` 初始值，不提前调用 setMode；loadDataset 移到 try 之外保证执行。
  3. `ChartContext.render()` 去掉 dataset null 的早退，始终调用 `renderer.render([])`；`renderer.render()` 把 `clearColor(白)` 提到 `total===0` 判断之前，无 pane 也清白屏。
  4. `registerPane/unregisterPane` 后调用新增的 `applyLayout()`：pane 元素晚于首次 layout 才升级时重新分配 rect（否则几何为空）。`layout()` 保存 size 并抽出 applyLayout。
  5. canvas/overlay 显式 z-index 1/2，错误文字不会被画布盖住；错误信息补充「请用 HTTP 访问」提示。
- 可观测性：index.html 新增 `#status` 状态标签，监听 `load-start` / `data-loaded` / `error` / `webglcontext-lost`；file:// 下直接红字提示。模块 import 加 `?v=2` 绕过浏览器缓存，verify.mjs 同步适配查询串。
- 复测：`npm run check` 全通过；无头 Chrome 截图 190KB（修复前 50KB 纯黑），JS 错误 0，状态「已加载 600519.SH · 2026-11-13」；页面可见 K 线蜡烛 + MA5/MA20、VOL/AMOUNT/MACD 三副图、150 档筹码峰横条、集合竞价折线与匹配量柱、交易明细虚拟表格、十档盘口、示例数据信息。
